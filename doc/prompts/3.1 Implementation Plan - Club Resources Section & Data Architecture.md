# Implementation Plan: Club Resources Section & Department Data Architecture

Standardize both data sources as native JavaScript data files ([`js/departments-data.js`](../../js/departments-data.js) and [`js/clubs-data.js`](../../js/clubs-data.js)), add the `club_res` Google Drive link variable across all departments in `departments-data.js`, introduce a dedicated **"Club Resources"** sub-section within the ECA section of [`index.html`](../../index.html), and implement an interactive modal displaying department-wise clubs and their subsidiary wings.

---

## User Review Required

> [!NOTE]
> **Unified Architecture Adopted (`.js` Data Files)**:
> By defining [`js/clubs-data.js`](../../js/clubs-data.js) as a native JavaScript data object (`const clubsData = { ... };`), we achieve 100% architectural symmetry with `departments-data.js`.
> - **Zero CORS/Fetch Overhead**: Runs reliably whether accessed over HTTPS or opened directly from the filesystem (`file://`).
> - **Instantaneous Rendering**: No async fetch latency, no loading spinners, and no fallback boilerplate.
