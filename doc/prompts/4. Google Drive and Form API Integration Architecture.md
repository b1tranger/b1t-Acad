# 4. Google Drive and Form API Integration Architecture

## Turn 1: Planning, Architectural Design & Guide Creation

### User Request
```text
prepare an implementation plan to integrate Google Drive API for viewing Google Drive links within the website with conditional view after login, and Google Form API for form submissions in custom form within the website. Guide me step by step through the process. document that guide in @[d:\GitHub\[oU1TS]\b1t-Acad\doc] as a new text file.
```

### Thinking
- Analyzed the user requirements:
  1. Integrate Google Drive API for viewing Google Drive links (files and folders) within the website with conditional post-login gating.
  2. Integrate Google Form API (via a serverless, zero-cost Google Apps Script Web App bridge) for submitting responses and file uploads through a custom front-end form matching b1t-Acad's glassmorphic dark design.
  3. Formulate a comprehensive step-by-step setup guide covering Google Cloud Console configuration, OAuth 2.0 / GIS token authentication, Drive Viewer modal, Apps Script API bridge deployment, security, and PWA considerations.
  4. Document the complete guide in `doc/google-api-integration-guide.md`.
  5. Adhere to repository guidelines in `AGENTS.md`: create `implementation_plan.md`, dual-write to `doc/prompts/4.1 Implementation Plan - Google Drive & Form API Integration.md`, create session archive `doc/prompts/4. Google Drive and Form API Integration Architecture.md`, and generate a Git commit recommendation.
- Auth & Drive Viewer Architecture:
  - b1t-Acad is a client-side static web application. Google Identity Services (GIS) Token Client provides client-side OAuth 2.0 authentication without exposing secrets.
  - Gated Drive links intercept clicks, prompting unauthenticated visitors to sign in with Google.
  - Single file previews use Google's embedded viewer sandbox (`/file/d/{id}/preview`). Folder URLs query Google Drive API v3 (`files.list` with query `'FOLDER_ID' in parents and trashed = false`) to display a folder explorer inside an in-website modal.
- Custom Form & Google Forms/Drive Submission Architecture:
  - Evaluated official Google Forms REST API v1 vs Google Apps Script Web App. Official Forms API v1 requires server-side service account credentials and lacks an unauthenticated public submit endpoint.
  - Developed the Google Apps Script Web App architecture: `doPost(e)` receives JSON payloads, uploads binary attachments to a designated Google Drive folder, logs entries to Google Sheets / Google Form, handles CORS, and returns structured JSON responses.
- Authored the guide document in `doc/google-api-integration-guide.md`.
- Created the implementation plan artifact `implementation_plan.md` and dual-wrote to `doc/prompts/4.1 Implementation Plan - Google Drive & Form API Integration.md`.
