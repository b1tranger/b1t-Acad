# Implementation Plan - Google Drive & Google Form API Integration

Prepare a phased architectural integration to:
1. Gate and view Google Drive files and folders directly within the b1t-Acad portal using Google Identity Services (GIS) and Google Drive API v3 with conditional post-login access.
2. Replace external Google Form redirects with an embedded, glassmorphic custom in-website submission form backed by a zero-cost Google Apps Script Web App API bridge with Google Drive file uploads.
3. Provide a step-by-step setup guide documented in [`doc/google-api-integration-guide.md`](file:///d:/GitHub/%5BoU1TS%5D/b1t-Acad/doc/google-api-integration-guide.md).

---

## User Review Required

> [!IMPORTANT]
> **Client-Side Google Forms Architecture**: The official Google Forms REST API (`v1`) does not support unauthenticated public submission of responses from arbitrary front-end forms without user OAuth or server-side private keys. The established, industry-standard pattern for static sites (like GitHub Pages/Netlify) is a **Google Apps Script Web App bridge** that receives form data and file attachments over HTTPS POST, uploads them to your Google Drive, and appends the response to a linked Google Sheet or Form. We will provide the exact `Code.gs` script and step-by-step deployment instructions.

> [!NOTE]
> **Google Cloud Project Prerequisites**: To enable the Drive viewer and Google Sign-In, you will need to create a Google Cloud Project, enable the **Google Drive API (v3)**, and generate an **OAuth 2.0 Web Client ID** and **Restricted API Key** in the [Google Cloud Console](https://console.cloud.google.com/). We have documented the exact field-by-field instructions in the guide.

## Proposed Changes

### Phase 1: Authentication & Access Control

#### [NEW] [`js/auth-manager.js`](file:///d:/GitHub/%5BoU1TS%5D/b1t-Acad/js/auth-manager.js)
- Implement `AuthManager` with Google Identity Services (GIS) Token Client.
- Track authentication state in `sessionStorage` with token handling and user profile caching.
- Intercept Google Drive links (`a[href*="drive.google.com"]`), displaying a dark glassmorphic login-required modal for unauthenticated visitors.
- Provide dynamic login/logout header triggers and authentication state events (`auth-state-changed`).

---

### Phase 2: In-Website Google Drive Viewer

#### [NEW] [`js/drive-viewer.js`](file:///d:/GitHub/%5BoU1TS%5D/b1t-Acad/js/drive-viewer.js)
- Parse Google Drive URLs (differentiating between file IDs and folder IDs).
- Render responsive single-file previews using Google Drive's embedded preview sandbox (`/file/d/{id}/preview`).
- Implement dynamic Google Drive v3 Folder Explorer: queries the Drive API for children of folder IDs (`'FOLDER_ID' in parents and trashed = false`), rendering a navigable explorer inside a modal window with file sizes, types, and click-to-preview actions.

---

### Phase 3: Custom In-Website Submission Form

#### [NEW] [`js/submission-bridge.js`](file:///d:/GitHub/%5BoU1TS%5D/b1t-Acad/js/submission-bridge.js)

- Submit multipart/JSON payloads asynchronously via `fetch` to the Google Apps Script Web App endpoint.
- Provide inline loading indicators, error feedback, and success animations.
